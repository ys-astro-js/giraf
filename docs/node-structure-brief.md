# 노드 구조 개편 브리프

상태: 설계 확정, 구현 중 (2026-10-09). 반복은 2026-10-10에 반복 영역(3.5, 3.7)으로 개정
모드: **Operate**
시안: [Claude Design 캔버스](https://claude.ai/artifact/U8zoms2nQBDGuakC9od5K9)의 '구조 시안' 페이지(보드 1–7)
관련 문서: [워크플로 편집기](workflow-editor.md), [노드 스키마 v2](node-schema.md), [보정 포트](calibration-ports.md)

## 1. 작업과 사용자

IRAF를 배우는 학생이 캔버스에서 task를 연결해 워크플로를 만들고 실행합니다. 처음에는 노드가 서너 개지만 보정, 측광, 반복 처리가 붙으면 수십 개로 늘어납니다. 지금 노드는 항상 같은 크기로 모든 입력 행을 보여 주므로, 워크플로가 커지면 캔버스에서 흐름을 읽기 어렵습니다. 또 파일 입력이 노드 안에 숨어 있어서 그래프만 보고는 출처를 알 수 없습니다.

## 2. 결과와 근거

- 큰 워크플로도 한 화면에서 흐름(무엇이 어디로 가는지)을 읽을 수 있어야 합니다.
- 입력, 설정, 출력의 관계를 그래프에서 확인할 수 있어야 합니다. 파일과 측정값이 어디서 왔는지가 선으로 보여야 합니다.
- 필요한 부분만 펼쳐서 자세히 볼 수 있어야 합니다.
- 모든 동작은 노드 스키마와 IRAF 타입으로 정의하며, 특정 task를 위한 코드 경로를 만들지 않습니다.

## 3. 선택한 방향

시각 체계는 기존 GIRAF 체계(Pretendard, 중성색, 청록 주요 동작, 얇은 경계)를 유지합니다. 1차 시안 A의 행 구조를 바탕으로 C의 `이름 = 값` 표기와 D의 캡슐을 결합합니다.

### 3.1 노드 두 단계: 접힘과 펼침

| 단계 | 내용 | 높이 |
| --- | --- | --- |
| 접힘 | 상태 아이콘, 노드 이름, 결과 개수. 왼쪽 입력점 하나, 오른쪽 출력점 하나 | 40px 캡슐 |
| 펼침 | 머리(상태, 이름, 설명, 접기 버튼), 입력 행, 고정 파라미터, 출력 행, 결과 미리보기 | 내용에 따라 |

- 단계는 노드마다 저장합니다(`Instance.collapsed`를 사용). 상세 단계는 따로 두지 않습니다. 자세한 정보는 인스펙터가 맡습니다.
- 접힌 노드로 들어오는 연결선에는 입력 이름 라벨(`image V`, `coords`)을 선 위에 붙입니다. 라벨은 연결선 경로의 도착점 가까운 위치에 놓습니다.
- 노드 폭은 펼침 264px, 접힘 184px입니다. 긴 이름은 말줄임합니다. 노드 폭과 출력 포트의 기존 규칙(280px, 오른쪽 아래부터 쌓는 포트)은 이 구조로 대체합니다.
- 선택은 상태 테두리와 독립된 바깥 고리(2px, 간격 2px)로 표시해 실행 중, 경고, 오류 테두리와 겹치지 않게 합니다.

### 3.2 출력 행

출력도 입력처럼 노드 안의 행으로 보여 줍니다. 행은 오른쪽 정렬로 이름과 결과 개수를 표시하고, 연결점은 오른쪽 테두리에 둡니다. 이름 없는 기본 출력은 `결과`와 화살표 연결점을 씁니다. 사용자 추가 출력 포트도 같은 행 문법을 따릅니다.

### 3.3 결과 미리보기

펼친 노드에 완료된 영상 결과가 있으면 출력 아래에 썸네일 세 장과 `외 N개`를 표시합니다. 썸네일을 누르면 오른쪽 결과 탭에서 그 파일을 엽니다. 영상이 아닌 결과는 미리보기 없이 출력 행의 개수만 보여 줍니다.

### 3.4 고정 파라미터와 값의 흐름

**고정 파라미터**
- 인스펙터의 파라미터 행에서 고정을 켜면 노드의 고정 파라미터 구역에 `datapars.fwhmpsf  3.21` 형태로 표시합니다. 이름은 IRAF 원문, 값은 현재 값입니다.
- 노드에서는 보기만 하고, 행을 누르면 인스펙터에서 해당 필드를 열어 초점을 옮깁니다.
- 스키마 최상위 `pinned` 목록이 새 노드의 기본 고정 파라미터입니다. 인스턴스는 자기 목록을 저장합니다.

**값이 필요한 실제 경우** (M67 PSF 측광 기준)
- 필터마다 조금씩 다른 값을 써야 합니다(B와 V의 fwhmpsf).
- daoedit 같은 측정 결과를 모아 평균, 중간값을 내고 곱하거나 더해 daofind, phot의 파라미터로 씁니다.
- daofind에 쓴 datapars를 phot에서 그대로 씁니다.
- NCOMBINE, EXPTIME 같은 헤더 값을 그대로 쓰거나 계산에 넣습니다.
- readout noise, gain처럼 헤더에 없는 값은 사용자가 정합니다.

**값의 출처: 네 종류**

| 출처 | 정의 | 예 |
| --- | --- | --- |
| task 측정값 | task 스키마의 `value-output` 구성 요소. 텍스트 출력의 열(`from`, `column`)이나 출력 영상의 헤더 키워드(`keyword`)에서 읽습니다. 여러 개면 목록입니다. | daoedit의 `fwhm` 목록 |
| 헤더 값 노드 `giraf.header` | 들어온 파일에서 고른 키워드를 읽어 값으로 내보냅니다. | `NCOMBINE`, `EXPTIME` |
| 상수 노드 `giraf.value` | 사용자가 입력한 값입니다. 키워드 값마다 다른 값을 표로 주면 꼬리표가 붙은 값이 됩니다(3.5). | `readnoise 5.2`, `gain 1.4` |
| 계산 노드 `giraf.compute` | 값 입력을 받아 IRAF 식으로 계산합니다. `mean`, `median`, `min`, `max`, `stddev` 같은 모음 함수를 씁니다. | `median(fwhm)`, `4 * m`, `gain * NCOMBINE` |

**값을 받는 곳: 두 종류**
- 모든 task 파라미터는 IRAF 타입(real, int, string, bool)으로 값을 받을 수 있습니다. 받지 않게 할 파라미터만 스키마에서 `"connectable": false`로 막습니다.
- pset 노드: `datapars`처럼 여러 task가 함께 쓰는 IRAF pset을 노드로 꺼냅니다. pset 노드의 파라미터가 값을 받고, pset 출력(둥근 사각 연결점)을 daofind와 phot의 pset 입력에 연결하면 두 task가 같은 값을 씁니다. IRAF의 pset 의미를 그대로 따릅니다.
- 헤더 키워드 이름을 받는 파라미터(`datapars.exposure = EXPTIME`)는 IRAF 방식대로 키워드 이름을 적습니다. 값 노드가 필요 없습니다.

**꼬리표와 값**
- 값은 파일의 꼬리표(3.5)를 따라갑니다. 꼬리표가 붙은 파일에서 나온 측정값과 헤더 값은 꼬리표별 값(`B 3.38, V 3.07`)이 됩니다.
- 계산 노드는 꼬리표마다 따로 계산합니다. 반복 영역 안의 파라미터로 들어가는 값은 파일과 같은 경계 칩 규칙으로 회차의 값을 고릅니다.

**표시**
- 값 연결점은 마름모, 데이터 연결점은 원, pset 연결점은 둥근 사각형입니다.
- 값 연결선은 점선(둥근 점)이고 선 가운데에 현재 값을 표시합니다.
- 연결된 파라미터는 자동으로 노드에 고정되고, 연결을 끊기 전에는 고정을 해제할 수 없습니다. 인스펙터의 해당 필드는 연결된 출처를 보여 주고 직접 편집을 막습니다.

### 3.5 반복 영역

천문 전처리는 "헤더 값이나 장수로 나눠서 처리하고 다시 모으기"의 연속입니다. 이것을 반복 영역 하나로 표현합니다. 영역의 모양은 파이썬이나 CL 스크립트의 반복문과 같고, 나누고 짝짓는 규칙은 astropy의 `group_by`와 같습니다. 시안: 캔버스의 '반복 다시 생각하기' 페이지 L7–L9.

```python
for exp, g in group(darks, "EXPTIME"):                        # 영역 EXPTIME마다, dark는 나눠서
    parts = [darkcombine(c, zero=bias, combine="median")       # bias는 모두에
             for c in chunks(g, 5)]                            # 안쪽 영역 5장씩
    master_dark[exp] = darkcombine(parts, combine="average")   # 안쪽 영역을 나가면 모임
for (filt, exp), sci in group(science, "FILTER", "EXPTIME"):
    ccdproc(sci, zero=bias, dark=master_dark[exp], flat=master_flat[filt])   # 꼬리표로 짝
```

**영역**
- 반복 영역은 그룹과 같은 컨테이너이고 테두리는 점선입니다. 머리에는 무엇마다 반복하는지(`EXPTIME마다`, `5장씩`, `FILTER, EXPTIME마다`)와 진행(`4회 중 2번째`)을 표시합니다.
- 경계 연결점은 없습니다. 바깥 연결선은 안쪽 작업의 입력 행에 바로 연결하고, 안쪽 작업의 출력도 바깥 작업에 바로 연결합니다.
- 영역은 겹칠 수 있습니다. 안쪽 영역은 바깥 영역의 회차 안에서 다시 나눕니다. 겹친 모양이 스크립트의 들여쓰기와 같습니다.
- 영역을 끌어서 다른 영역 안에 놓거나 밖으로 꺼냅니다. 영역을 선택한 채로 반복을 추가하면 그 안에 만듭니다. 바깥 영역을 옮기거나 접으면 안쪽 영역도 함께 움직이고 숨습니다.

**무엇마다**
- 기준은 목록이고, 여러 개면 값의 조합마다 한 회차입니다.

| 기준 | 회차 | 꼬리표 이름 |
| --- | --- | --- |
| 헤더 키워드 | 키워드 값마다 | 키워드 이름 (`EXPTIME`) |
| 식 | IRAF 식 결과 값마다 | 영역에서 정한 이름 |
| N장씩 | 정한 순서(파일 이름 또는 헤더 키워드)로 N장씩. 남는 파일은 마지막 회차 | `묶음` (1부터) |
| 파일마다 | 한 장씩 | `파일` |
| N번 | 정한 횟수만큼(최대 1000회). 나눌 파일 없이 반복 | `회차` (1부터) |

- 설정 탭은 기준을 한 줄씩 보여 주고 `+헤더 키워드`, `+식`, `+N장씩`, `+파일마다`, `+N번`으로 더합니다. `+헤더 키워드` 메뉴는 나눌 파일의 헤더에서 찾은 키워드를 값과 함께 보여 줍니다. 값이 하나뿐인 키워드와 파일마다 값이 다른 키워드는 `더 보기`에 접어 두고, 기기 헤더 매핑(`EXPTIME`, `FILTER` 등)의 키워드와 모든 파일에서 값이 같은 키워드(`EXPOSURE`)는 매핑의 키워드 하나로 보여 줍니다.
- 설정 탭에 회차 목록(`15  10장`, `30  10장`)을 미리 보여 줍니다. 식과 조건은 파일에 있는 헤더 값으로 계산할 수 있으면 미리 보여 주고, 아니면 `실행하면 정해집니다`입니다.
- `조건에 맞는 파일만`(IRAF 식, `EXPTIME > 30`)을 정하면 나눌 파일 중 조건에 맞는 파일만 영역에 들어갑니다. 기준 없이 조건만 있으면 회차는 하나입니다.

**나눌 파일**
- 영역 설정에서 나눌 파일을 직접 고릅니다. 후보는 영역 안으로 연결이 들어오는 바깥 출처(작업 출력 또는 파일 노드)입니다. N번만 쓰는 영역은 나눌 파일이 없습니다.
- 나눌 파일에서 영역 안으로 들어오는 연결은 모두 그 회차의 파일만 받습니다. 한 출처를 안쪽 작업 여러 개에 연결해도 같은 회차의 파일입니다.
- 나눌 파일에 영역 기준과 같은 이름의 꼬리표가 있으면 헤더 대신 꼬리표 값으로 나눕니다.
- 나눌 파일을 고르지 않았으면 영역의 오류 진단으로 알립니다.

**경계 칩**
- 연결선이 영역 테두리를 넘는 자리에 칩을 그립니다. 칩을 누르면 메뉴에서 받는 방식을 바꿉니다. 겹친 영역을 넘는 연결은 테두리마다 칩이 있습니다. 영역 밖으로 나가는 연결에는 칩이 없습니다.

| 칩 | 받는 것 | 기본으로 되는 경우 |
| --- | --- | --- |
| `나눠서` | 그 회차의 파일 | 설정에서 고른 나눌 파일 |
| `<키워드>로 짝` | 회차 값과 같은 값의 파일. 꼬리표가 있으면 꼬리표, 없으면 헤더 값으로 비교 | 출처가 영역 기준과 같은 이름의 꼬리표를 가질 때 |
| `모두에` | 모든 회차에 같은 파일 | 그 밖 |

- 짝은 영역 기준 중 하나 이상으로 짓습니다(메뉴에서 체크). 값은 둘 다 수로 읽히면 수로(`15`와 `15.0`은 같음), 아니면 앞뒤 공백을 뺀 글자로 비교합니다.
- 메뉴에서 `나눠서`를 고르면 영역의 나눌 파일이 그 출처로 바뀝니다.
- 값 연결도 같은 칩 규칙을 따릅니다. 꼬리표별 값은 `…로 짝`이면 회차의 값 하나를 받습니다.

**꼬리표와 다시 모이기**
- 영역 안에서 만든 결과에는 그 회차의 값이 꼬리표(`{EXPTIME: 15, 묶음: 1}`)로 붙습니다. 겹친 영역에서는 바깥 영역의 꼬리표도 함께 붙습니다.
- 영역 밖으로 나가는 연결은 모든 회차의 결과를 목록 하나로 넘깁니다. 꼬리표는 그대로 남아서 다음 영역의 짝짓기와 나누기에 쓰입니다.
- 회차 값은 값으로도 씁니다. 영역 머리의 기준마다 있는 마름모 연결점(`EXPTIME`, `회차`)에서 그 회차 값이 나와 안쪽 파라미터에 연결됩니다.
- 안쪽 작업의 출력 이름에 쓴 `{꼬리표 이름}`은 회차 값으로 바뀝니다(`Dark{EXPTIME}_{묶음}.fits` → `Dark15_1.fits`).

**진단**
- 실행 전에 알 수 있는 짝 문제는 칩과 받는 작업의 경고로 알립니다.
  - 회차에 맞는 파일이 없을 때: `V 15 회차에 맞는 dark가 없습니다.`
  - `모두에`인 출처가 영역 기준에 없는 꼬리표를 가질 때: `Master Dark는 EXPTIME마다 다릅니다. 영역에 EXPTIME을 더하면 짝을 지을 수 있습니다.`
  - `모두에`인 연결이 파일 하나만 받는 입력(`multiple`이 아닌 입력)에 여러 장을 줄 때: `Master Flat가 여러 장입니다. 칩에서 짝을 고르세요.`
  - 예전 문서의 묶음 포트나 보정 그룹 포트에서 한 값만 받던 연결: `묶음에서 한 값만 받던 연결이 전체를 받게 되었습니다.` 칩에서 받는 방식을 고르거나 연결을 다시 이으면 사라집니다.
- 앞 작업이 아직 실행되지 않아 파일을 모르면 실행할 때 같은 규칙으로 판단합니다.

**대체하는 것**
- 출력 포트의 나누기(묶음 포트), 보정 그룹 포트(`calibration-groups`), 값 노드의 나누기 설정, 반복의 경계 연결점(`items`, `이번 파일`, `결과`), 숫자 반복과 분기 컨테이너는 반복 영역으로 대체합니다.
- 반복 밖에서 안쪽으로 들어오는 파일을 헤더 값으로 몰래 맞추던 규칙은 없앱니다. 모든 짝은 칩에 보입니다.
- IRAF 자체의 subset 처리(flatcombine `subsets`, ccdproc의 flat 선택)는 IRAF 파라미터로 그대로 둡니다.

### 3.6 그룹을 복합 노드로

- 그룹(subflow)을 접으면 그룹 색 테두리의 복합 노드 하나가 됩니다. 머리에는 그룹 아이콘, 이름, 작업 수, 종합 상태를 표시합니다.
- 복합 노드의 포트는 그룹 경계를 넘는 연결에서 자동으로 만듭니다. 입력 행은 내부 대상의 역할 이름, 출력 행은 내부 출처의 출력 이름을 씁니다.
- 펼치면 지금의 그룹 영역으로 돌아갑니다. 영역 머리에는 접기 버튼과 기존 그룹 실행 버튼이 있습니다.

### 3.7 숫자 반복과 조건

별도 컨테이너를 두지 않고 반복 영역(3.5)의 설정으로 표현합니다.

- 숫자 반복은 기준이 `N번`인 영역입니다. 정한 횟수만큼 안쪽 작업을 실행하고, 영역 머리의 마름모 연결점에서 지금 몇 번째인지(`회차`, 1부터)가 나옵니다.
- 조건은 영역의 `조건에 맞는 파일만`입니다. 참과 거짓 두 칸은 두지 않습니다. 반대 경우가 필요하면 반대 조건의 영역을 하나 더 둡니다.
- 값 하나로 작업 전체를 실행할지 정하는 조건(`fwhm > 4.0`이면 실행)은 이번 범위에 넣지 않습니다.

### 3.8 입력 출처: 파일은 항상 파일 노드

- 파일은 항상 파일 입력 노드(`giraf.file_input`)로 캔버스에 둡니다. task 노드의 입력 행은 연결된 출처만 표시합니다.
- 파일 선택기에서 고르거나 파일을 입력 행에 끌어 놓으면, 파일 입력 노드를 만들어 대상 노드 왼쪽에 놓고 연결합니다.
- 표현식, 직접 입력 텍스트, 커서 명령은 지금처럼 입력 행 안에 남습니다. 표현식 값은 고정폭 글꼴로 표시합니다.
- 파일 입력 노드는 기본으로 접힌 상태(파일 아이콘, 이름, 파일 수)로 만듭니다.
- 파일 연결선 숨기기: 켜면 파일 노드에서 나가는 연결선을 그리지 않습니다. 대신 받는 입력 행에 파일 아이콘과 파일 노드 이름을 표시합니다. 그 입력 행이나 파일 노드에 포인터를 올리거나 선택하면 해당 연결선만 그립니다. 연결점은 연결된 상태로 채워 둡니다.

### 3.9 한꺼번에 접고 펼치기

- 상단 도구 막대에 `노드 보기` 그룹을 배치와 그룹 사이에 둡니다. 버튼 하나로 메뉴를 엽니다.
- 메뉴 항목: `모두 펼치기`, `모두 접기`, `선택한 노드만 펼치기`, 구분선, `축소하면 자동으로 접기`, `파일 연결선 숨기기`. 켜고 끄는 항목은 메뉴의 체크 표시로 나타냅니다.
- 자동 접기를 켜면 배율 60% 미만에서 모든 노드를 접힌 모양으로 그립니다. 확대·축소가 끝난 시점에 판단해서 조작 중에 노드가 깜박이지 않습니다. 저장된 단계는 바꾸지 않습니다. 이 설정은 워크플로가 아닌 브라우저에 저장하는 보기 설정이며 기본값은 켜짐입니다.

## 4. 범위와 경계

- 범위: task 노드, 파일 입력과 파일 저장 노드, 그룹, 연결선 표현, 노드 보기 메뉴, 인스펙터의 고정 토글과 값 연결 표시, 저장 형식 이관.
- 유지: 시각 토큰, 연결 동작(클릭 연결, 끌어 놓기, Escape 취소, 호환성 검사), 진단 표시 방식(경고와 오류는 테두리와 상태 아이콘, 내용은 툴팁과 인스펙터), 인스펙터 탭 구성, 실행 기록과 결과 탭.
- 하지 않는 것: 노드 안의 직접 편집 입력란, 새 배지와 안내 문구, 노드별 실행 버튼, 상세 단계, 접기에 따른 자동 재배치.
- 기존 워크플로와의 호환 제약은 없습니다. 기존 문서는 불러올 때 새 형식으로 이관합니다.

## 5. 상태와 데이터 범위

- 노드 상태: 실행 전, 대기, 실행 중, 입력 대기, 완료, 실패, 중단, 경고, 오류. 접힘과 펼침 모두 같은 아이콘과 테두리 규칙을 씁니다.
- 연결 중: 접힌 노드 위로 연결을 끌고 가면 그 노드를 잠시 펼쳐 입력 행을 고르게 하고, 벗어나면 다시 접습니다. 호환 입력이 하나뿐이면 펼치지 않고 바로 연결합니다.
- 검색: 일치하는 접힌 노드는 그대로 두고 나머지를 흐리게 합니다.
- 범위: 입력 행 0–8개, 영역 회차 1–수백 회, 영역 겹침 0–3단계, 고정 파라미터 0–6개, 출력 1–6개, 결과 0–수백 개, 그룹 안 작업 2–20개. 긴 이름은 말줄임하고 전체 이름은 툴팁으로 보여 줍니다.

## 6. 상호작용과 배치

- 노드 머리의 접기 버튼, 캡슐을 두 번 누르기, 선택한 노드에서 단축키로 단계를 바꿉니다. 단축키는 구현 전에 기존 단축키와 겹치지 않게 정합니다.
- 펼칠 때 머리 위치를 기준으로 아래로 늘어납니다. 다른 노드는 움직이지 않습니다. 겹침은 자동 배치로 정리합니다.
- 자동 배치(ELK)는 현재 단계의 실제 크기와 포트 좌표를 사용합니다.
- 단계 전환 애니메이션은 `--motion-shift`, 움직임 줄이기 설정에서는 즉시 바뀝니다.
- 미니맵, 전체 보기, 연결선 좌표는 노드 geometry 계산 하나를 공유합니다.

## 7. 제약과 열린 결정

확정한 항목(2026-10-09):
- 고정 파라미터의 `pinned` 목록과 `connectable`.
- 반복은 반복 영역 하나입니다(2026-10-10 개정, 3.5). 스키마에서는 흐름 구성 요소 `foreach`를 가진 GIRAF 노드 `giraf.foreach`로 정의하고, 안쪽 작업 목록은 워크플로 문서에 저장합니다. `giraf.for`, `giraf.if`와 출력 포트의 `partition`은 없앱니다.
- 영역 설정은 `draft.flow = { criteria, split, condition }`입니다. `criteria`의 항목은 `{keyword}`, `{expression, name}`, `{count, order}`, `{each: true}`, `{times}`이고, `split`은 나눌 파일의 출처(`{taskId, outputRole}`)입니다.
- 경계 칩은 연결에 저장합니다: `Connection.flow = { "<영역 id>": { "mode": "all" | "match", "keys": [...] } }`. 저장하지 않은 영역은 3.5의 기본 규칙을 따르고, `나눠서`는 영역의 `split`으로 정합니다.
- 예전 문서는 열 때 옮깁니다. `keywords`는 헤더 키워드 기준이 되고, `items`에 연결한 출처는 `split`이 되며, `이번 파일`과 `결과` 연결점을 거친 연결은 출처와 대상을 바로 잇는 연결이 됩니다. `for`는 같은 횟수의 `N번` 영역이 되고, `if`는 조건 영역이 됩니다(거짓 칸에 작업이 있으면 반대 조건의 영역을 하나 더 만듭니다). 묶음 포트와 보정 그룹 포트에서 한 값만 꺼내던 연결은 일반 연결로 바뀌고 `Connection.widened`가 붙어 진단으로 알립니다. 헤더 값으로 짝을 짐작하지 않습니다.
- 저장 형식 v2: `Connection.source.kind = "files"`를 파일 입력 노드와 연결로 이관합니다. 그룹과 컨테이너에 `collapsed`, 포트별 묶음 펼침, 인스턴스별 고정 파라미터, 화면 설정에 파일 연결선 숨김을 추가합니다. `TaskMap.version`을 2로 올립니다.
- 자동 접기 배율은 60%입니다.

- 값의 흐름(3.4): 값 출처는 task 측정값, 헤더 값 노드, 상수 노드, 계산 노드의 네 종류이고, 여러 task가 함께 쓰는 값은 pset 노드로 공유합니다.
- `value-output` 선언 형식: `{ "type": "value-output", "name": "fwhm", "kind": "real", "from": "<출력 이름>", "column": "FWHM" }` 또는 `"keyword": "…"`. task별 열 이름은 각 task의 스키마를 작성할 때 정합니다.
- 계산 식은 IRAF 식 문법을 그대로 쓰고, 모음 함수(`mean`, `median`, `min`, `max`, `stddev`)만 GIRAF가 추가합니다.

구현할 때 정할 세부 사항: 노드 단계를 바꾸는 단축키, task별 `value-output` 열 이름.

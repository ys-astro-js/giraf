# 워크플로 편집기

상태: 사용자 방향을 반영한 구현 문서 · 2026-09-16
모드: **Operate**
대상: `web/src/App.tsx`, `index.css`, `components/task-map-view.tsx`, `components/task-inspector.tsx`

## 목적과 방향

사용자가 노드 캔버스에서 임의의 IRAF 워크플로를 구성하고 오른쪽 inspector에서 선택한 task의 실제 설정을 제어합니다. 분기, 독립 작업, 같은 task의 여러 인스턴스를 표현합니다. 영상 보정은 가능한 사용 사례이며 고정된 제품 순서가 아닙니다. 기존 단색 Inter·Base UI 체계를 유지합니다.

## 주 사용 동선

1. 왼쪽 파일 또는 task 탭에서 자료를 선택하거나 task를 추가합니다. 두 탐색 목록은 선택한 탭에 따라 교대 표시됩니다.
2. 캔버스의 task 노드를 선택하고 이동하거나 입출력 포트로 연결합니다. 제목의 드래그 핸들과 Alt+방향키로 위치를 조정할 수 있습니다. 삭제 및 되돌리기를 제공합니다.
3. 우측 inspector에서 입력·표현식, 출력과 task 파라미터를 편집합니다. 입력은 현재 사용하는 파일·표현식·노드 출력을 한 줄로 표시하고, 그 컨트롤을 눌러 변경합니다. Boolean은 switch로 편집하고 관련 보정 파일·영역은 해당 조건이 활성화될 때 보여 줍니다.
4. 워크플로우 실행을 한 번 눌러 서버에서 연결 순서대로 실행합니다. 각 연결은 이번 실행의 결과를 다음 입력으로 전달합니다. 개별 점검은 이 작업만 실행을 사용합니다.

## 화면 구성과 공간

- **중앙:** task 인스턴스 하나당 노드 하나입니다. 노드 안에 작업명·기능 설명·상태, 입력 역할별 출처, 출력 개수·결과 보기를 순서대로 배치합니다. 입력별 연결점과 오른쪽 출력 연결점이 연결을 표현합니다. 노드 폭은 280px이며 입력 역할별 행 수에 따라 높이가 달라집니다. 선택은 경계로 표현하며 비활성 연결은 점선으로 표시합니다.
- **왼쪽:** 공식 Sidebar 블록 구성을 따라 SidebarMenu·SidebarGroup·Collapsible 하위 메뉴를 사용합니다. Sidebar는 offcanvas로 접히며 모바일은 기본 Sheet로 표시합니다.  폭은 Resizable로 조절합니다. 기본 256px, 범위 224–360px이고 상단 버튼으로 접습니다.
- **오른쪽:** 캔버스와 설정을 Resizable로 나눕니다. 설정 패널은 독립적으로 세로 스크롤하며 실행 헤더는 상단에 유지됩니다.
- **하단:** 실행 기록은 기본 40px로 접히며 Resizable로 높이를 조절합니다.
- **767px 이하:** 상단 SidebarTrigger로 자료·작업 탐색 Sheet를 엽니다. 작업 영역에서는 워크플로우/설정을 전환합니다.
- 검색·자동 배치·워크플로우 실행은 툴바 한 줄에 표시합니다. 목록 보기, 중복 작업 추가 버튼, 작업 이름 편집은 제거했습니다.
- 전역 알림과 삭제 되돌리기는 shadcn Toast로 표시합니다. 삭제 알림은 사용자가 닫을 때까지 유지됩니다.

## 편집과 실행의 계약

- 초안·파라미터·전처리·패키지·backend 설정의 인스턴스별 의미와 기존 실행 계층을 유지합니다.
- 기존 초기 파라미터를 보존합니다. 조건부 필드를 숨겨도 저장된 값을 지우지 않습니다.
- 전체 파라미터는 검색 가능한 폼으로 접근합니다. 초기값 비교 표, 선택됨 배지, 반복된 저장·실행 안내문을 기본 편집 영역에 쌓지 않습니다.
- 워크플로우 실행은 설정 스냅샷으로 진행하며, 노드 연결에는 이번 실행에서 만든 결과를 자동 전달합니다. 실행 기록에는 각 작업이 실제 사용한 파일을 보존합니다. 브라우저 새로고침 후에도 서버 실행은 이어집니다.
- 연결 해제·노드 삭제는 파일 자체 삭제를 뜻하지 않습니다. 파일 정책과 backend 실행 의미는 기존 구현을 따릅니다.

## 확인 범위

관련 UI 테스트 24개, TypeScript 검사와 프로덕션 빌드가 통과했습니다. 브라우저에서 노드 이동·삭제·되돌리기·연결, 설정 편집과 데스크톱·태블릿·모바일 배치를 확인했습니다. 실제 IRAF 계산은 이번 UI 변경에서 재실행하지 않았습니다.

## 노드 직접 연결과 오른쪽 결과 패널 (2026-09-16)

사용자 결정: 결과는 오른쪽 결과 패널에서 열고, 연결 가능한 입력이 하나면 즉시 연결합니다.

- 출력 연결점을 클릭한 다음 목표 노드를 클릭하거나, 출력 연결점을 목표 노드로 끌어 놓습니다. 출처와 목표가 정해진 뒤에는 해당 목표의 활성·호환 입력만 선택합니다. 하나면 즉시 연결하며 여러 개면 목표 카드의 입력 행에서 고릅니다. Escape, 빈 공간 클릭, 연결 취소로 종료합니다.
- 노드 출력은 해당 노드의 실제 출력입니다. 영상 작업의 텍스트 실행 보고서는 영상 연결에 섞지 않으며, 결과 패널에서는 보고서를 포함한 모든 생성 파일을 볼 수 있습니다. 최신 실행이 완료되지 않았으면 다음 실행의 출력 연결로 취급합니다.
- 자기 자신·순환 연결·종류 불일치·확인된 복수 출력을 단일 입력으로 전달하는 연결은 변경 전에 거부합니다. 비활성 보정 입력은 선택 후보에서 제외합니다. 기존 입력을 교체하면 해당 역할만 바꾸고 교체 사실을 표시합니다.
- 결과 보기는 결과 수와 관계없이 노드를 선택하고 오른쪽 결과 탭을 엽니다. 파일 목록에서 영상·텍스트·그래프를 같은 패널에서 확인합니다. 미실행·실행 중·실패·중단·빈 결과를 구분하며, 이전 성공 실행을 최신 결과로 대신 보여 주지 않습니다.
- 카드의 기능 설명과 상태는 독립적으로 유지합니다. 입력별 연결점, 카드 높이, 연결선 좌표, 자동 배치, 전체 보기는 같은 geometry 계산을 사용합니다. 커진 카드가 기존 저장 위치에서 겹치는 경우 표시 위치를 보정합니다. 배율 도구는 캔버스 아래 별도 행에 놓습니다.
- 모바일에서는 결과 보기가 상세 영역으로 전환됩니다. 작은 캔버스의 최초 배율은 읽을 수 있는 범위를 유지하고 전체 보기는 사용자가 선택할 수 있습니다.

검증: 구현 전에 회귀 테스트 15개와 화면 인수 조건을 작성했습니다. 새 회귀 테스트와 기존 관련 동작 테스트 44개가 통과했고 TypeScript 검사·프로덕션 빌드가 통과했습니다. 전체 UI 검사에 포함된 전역 typography 금지 검사 1개는 현재 UI 스타일과 충돌하여 실패합니다. 검사 규칙을 완화하지 않았습니다. 브라우저에서 오른쪽 결과 패널, 다중 입력 선택, 단일 입력 즉시 연결, 포인터 드래그 교체, Escape 취소, 텍스트 결과를 확인했습니다. 전체 보기의 카드 겹침·잘림은 0건입니다. 실제 IRAF 계산은 재실행하지 않았습니다.


## UI 정돈 (2026-09-16)

- 파일 선택은 경로 한 줄·목록 도구·목록·고정 적용 버튼으로 구성합니다. 미리보기는 좁은 화면에서도 열리며 선택을 유지합니다.
- 영상은 기본 탭으로 열고 단일 영상의 제목·저장을 중복 표시하지 않습니다. 표시·통계는 접을 수 있는 패널에서 확인하고, 프로파일은 넓은 하단 영역에 표시합니다. IRAF 통계 실행은 통계 패널에 두고, 헤더는 상단 탭에서 확인합니다.
- 좌표 입력과 방향키로 픽셀을 조사합니다. Shift+방향키는 10픽셀 이동이며, 조사 위치 선택 모드에서는 Enter 또는 선택 버튼으로 적용합니다.
- 선택한 노드를 다시 보여 주는 버튼과 패널 크기 변경 시 최소 스크롤 보정을 제공합니다.
- UI 문구는 짧은 이름·값·상태·복구 동작에 한정합니다. 필드 옆 설명 문단이나 프로그램 내부 동작을 해명하는 문구를 추가하지 않습니다. 빈 ccdtype은 ‘모든 유형’으로 표시하며 실제 값은 빈 문자열을 유지합니다.


### 영상 뷰어 공간 배분

파일명·영상/헤더·비교·입력 재사용·저장은 하나의 상단 바에 배치하고 종료는 닫기 하나로 제공합니다. 영상 위에 배율 조작과 픽셀 상태를 배치하고, 표시·통계는 접을 수 있는 패널로 제공합니다. 좌표 입력은 픽셀 상태에서 열며, 프로파일만 하단 분석 영역을 사용합니다.

## 데스크톱 영상 뷰어

사용 환경은 IRAF를 실행하는 데스크톱이며 모바일은 설계·검증 대상에서 제외합니다. 확대·배율·맞춤은 캔버스 가장자리 오버레이에 배치합니다. 표시 변환과 범위는 접을 수 있는 표시 패널, 통계는 같은 도킹 영역, 좌표 입력은 픽셀 상태 옆 작은 편집 영역, 프로파일은 축이 있는 넓은 하단 영역을 사용합니다. 파일 동작은 상단에서 제공하며 종료 동작은 하나로 유지합니다.


## 노드 정보·연결 정돈 (2026-09-16)

사용자 결정: 일반 노드 선택은 현재 설정/결과 탭을 유지합니다. 입력 행 선택은 해당 설정을 바로 엽니다.

- 결과 보기 버튼을 제거했습니다. 결과는 오른쪽 결과 탭으로 접근하며, 노드를 바꿔도 현재 탭을 유지합니다.
- 입력 행 클릭은 설정 탭의 해당 입력 편집기를 펼치고 초점을 이동합니다. 비활성 보정 입력은 보정 스위치로 이동하며 저장된 값을 자동 변경하지 않습니다.
- 출력 선택 직후 모든 호환 입력을 바로 선택할 수 있습니다. 입력 클릭·입력 행으로 드래그·파일 드롭 모두 지정한 역할을 연결하며, 카드 빈 곳을 통한 단일 입력 연결은 보조 경로로 유지합니다.
- 후보 입력은 연결/교체 문구로 표시하고 hover·초점에서 강조합니다. 카드 전체의 청록 테두리와 중간 선택 강조를 제거했습니다. Escape는 안내 버튼에 초점이 있을 때도 연결을 취소합니다.
- 제목/입력/상태·출력의 세 구역을 유지합니다. 완료 등 실행 상태와 영상·파일 개수를 하단에 묶고, 입력 기술 키와 연결선 라벨의 시각적 중복을 제거했습니다. 접근성 연결 이름은 보존합니다.
- 노드 헤더·푸터 높이와 연결점 geometry를 함께 줄였습니다. 연결 안내는 고정 높이여서 시작·취소·완료 중 노드 위치가 변하지 않습니다.

검증: 구현 전 인수 조건과 회귀 테스트를 작성했습니다. 관련 테스트 50개, TypeScript·프로덕션 빌드가 통과했으며 layout detector는 0건입니다. 전체 UI 검사는 55개 통과, 기존 전역 typography 금지 검사 1개 실패입니다. 1280×720과 390×844에서 입력 편집기 열림/초점, 탭 유지, 카드 배치, 가로 넘침 없음과 연결점 정렬을 확인했습니다. 클릭 및 드래그로 기존 Bias/Dark 입력의 동일 출처 재연결을 확인했고 다른 입력을 보존했습니다. 연결 전후 노드 좌표 변화는 0이며 Escape 취소를 확인했습니다. 실제 IRAF 계산과 파일 드롭의 브라우저 검증은 수행하지 않았습니다.


### 입력 연결 미리보기와 완료 아이콘 (2026-09-16)

## IRAF 설정 편집 정리 (2026-09-17)

모드: Operate. 사용자가 critique의 추천안을 선택했습니다.

- 우측 상단의 `전체 설정`으로 넓은 편집창을 엽니다. 기본 화면은 입력·출력·task별 주요 파라미터와 활성 보정 입력을 표시합니다. imcombine의 선택 입력과 imalign의 tuning 파라미터 등은 전체 편집기에서 접근합니다. 이미 연결된 선택 입력은 기본 화면에도 유지합니다.
- 전체 편집기는 task·ccdproc 전처리·pset·package·헤더 매핑의 원문 이름과 도움말을 검색하고 변경한 값만 필터링합니다. 비활성 종속 값도 검색할 수 있으며 검색·닫기로 값을 지우지 않습니다. 편집은 해당 작업에 즉시 반영합니다.
- IRAF 식별자는 원문을 주 라벨로 사용합니다. 원문 필드 설명은 입력 바로 아래에 항상 표시하고 필수 항목은 라벨의 별표로 한 번만 표시합니다. 삭제 경고는 유지합니다. 이름·값을 정렬하며 좁은 편집창은 한 열로 전환합니다.
- 헤더와 검색은 스크롤 밖에 고정하고 본문 하나만 스크롤합니다. 기존 초기화·초기화 취소, 파일·표현식·노드 입력 및 실행 payload를 보존합니다.
- 이 절차는 UI의 표시 우선순위만 정합니다. PDF의 수치와 절차를 전역 기본값으로 적용하지 않습니다.

- 기본 설정과 전체 설정에서 텍스트 입력·선택창은 라벨 → 입력 → 설명의 세로 순서로 표시합니다. 스위치는 라벨과 같은 줄 오른쪽에 두며, 설명은 그 줄 아래에 표시합니다. 이 규칙은 화면 폭에 관계없이 유지합니다. 검색 도구 모음의 필터는 폼 필드와 구분합니다.

### 출력 포트·경로·기본 배율 정돈

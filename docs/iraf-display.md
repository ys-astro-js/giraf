# IRAF 디스플레이

GIRAF는 IRAF의 영상 표시 장치(ds9, ximtool) 역할을 직접 합니다. `display`, `tvmark`처럼 영상 표시를 쓰는 작업은 IRAF가 그린 결과가 그대로 GIRAF의 디스플레이 창에 나타납니다. GIRAF가 흉내 내서 그리지 않습니다.

## 동작

- 서버가 시작될 때 전용 유닉스 소켓(`$TMPDIR/giraf-<pid>.imt`, 권한 600)에서 IIS(imtool) 프로토콜 서버를 엽니다(`giraf/display.py`).
- 서버 프로세스의 `IMTDEV`를 이 소켓으로 지정합니다. GIRAF가 실행하는 CL·PyRAF 작업만 이 값을 물려받으므로, 사용자가 터미널에서 쓰는 IRAF와 ds9에는 영향이 없습니다.
- 프레임 1–16은 앱 전체에서 유지됩니다. ds9처럼 `display`가 올린 프레임 위에 다음 작업의 `tvmark`가 그립니다. 서버를 재시작하면 비워집니다.
- 프레임 크기는 설치된 `dev/imtoolrc`의 `stdimage` 설정을 따릅니다. 색은 IRAF 표시 LUT(1–200 회색조, 201–217 그래픽 색)를 사용합니다.
- 비정상 종료로 남은 소켓 파일은 다음 시작 때 지웁니다.

## 화면

디스플레이 프레임은 표준 영상 뷰어의 자산(`display:N`)으로 열립니다. `/api/info`, `/api/image`, `/api/pixel`이 이 id를 디스플레이 서버로 보내므로 확대·이동·픽셀 조사와 도구 막대가 파일 뷰어와 같습니다. 이미 IRAF가 그린 8비트 프레임이라 표시 범위·통계·프로파일 도구(`analysis`)는 숨기고, 픽셀 조사는 IIS WCS로 계산한 IRAF 영상 좌표를 표시합니다. 프레임이 다시 그려지면 `revision`으로 보기 상태를 유지한 채 영상만 갱신합니다.

- 작은 창: 처음에는 워크플로우 캔버스 오른쪽 아래, 미니맵 위에 뜹니다. IRAF가 처음 그리면 나타나고 마지막으로 쓴 프레임을 따라갑니다. 왼쪽 위 이동 핸들로 옮기고 오른쪽 아래 모서리로 크기를 바꿉니다(방향키도 사용, Shift는 크게). 위치와 크기는 브라우저에 저장하며 캔버스 밖으로 나가지 않게 맞춥니다.
- 최소화: 창을 숨기고 캔버스 왼쪽 아래 보기 도구의 디스플레이 버튼으로 다시 엽니다.
- 최대화: 파일 뷰어와 같은 대화상자 틀에서 프레임 제목, 프레임 전환, 원래 크기로 버튼을 뷰어의 떠 있는 줄에 둡니다.
- 닫기: 디스플레이를 종료합니다. ds9 창을 닫을 때처럼 모든 프레임을 비우며(`POST /api/display-close`), IRAF가 다시 그리면 새로 나타납니다.
- 제목의 실행 폴더 사본 이름은 디스플레이 소켓에 연결한 IRAF 프로세스의 작업 폴더(`sources.json`)로 원본 이름으로 바꿉니다. 여러 작업이 동시에 실행돼도 정확합니다.

## 제한

- IIS 프로토콜의 커서 읽기는 아직 연결하지 않았습니다. 디스플레이 소켓으로 커서를 읽는 작업에는 `q`를 돌려줍니다. 대화형 실행은 아래의 텍스트 커서 모드를 씁니다.

## 대화형 실행 (커서 세션)

범용 작업에서 `interactive=yes`로 실행하면 IRAF의 커서 루프를 디스플레이 창에서 진행합니다(`psf`의 별 고르기와 승인·거절, `ccdproc`의 대화형 overscan 피팅 등). 작업마다 따로 만든 코드는 없습니다.

- 실행 스크립트에 `set stdimcur = "text"`, `set stdgcur = "text"`를 넣고 그래픽을 `>G interactive.gki`로 받습니다. IRAF는 커서를 읽을 때마다 터미널에 `Image cursor: [x y wcs] key [cmd]:`나 `Graphics cursor input:`을 묻고, CL 세션(`run_cl_terminal`)이 이를 `imcur`·`gcur` 입력 요청으로 바꿉니다. `[Hit return to continue, q to quit]` 같은 한 글자 질문은 `key` 요청입니다. 대화형 실행은 CL에서만 진행하며, PyRAF를 골랐다면 경고와 함께 CL로 바꿉니다.
- 입력을 기다리는 동안 디스플레이 창이 앞으로 오고, 하단 실행 기록이 그 실행의 로그를 엽니다. 실행 중인 로그는 끝을 따라갑니다(위로 스크롤하면 멈춤). 중단은 실행 기록의 중단 버튼을 씁니다.
- 영상 커서: IRAF처럼 디스플레이 프레임 위에 마우스를 올리고 키를 누릅니다. `display`로 띄운 현재 프레임을 쓰고, 프레임 위치를 IIS WCS(`transform`)로 IRAF 영상 좌표로 바꿔 `x y 1 key`로 보냅니다. 띄운 프레임이 없으면 작업의 첫 영상 입력을 보여 줍니다. 클릭한 위치도 기억해 마우스가 영상 밖에 있을 때 씁니다. 창 구성은 디스플레이 프레임과 같습니다(표준 뷰어, 좌표·확대 도구는 아래 바).
- 그래픽 커서: 창이 작업의 최근 GKI 그림으로 바뀌고 키를 `0 0 1 key`로 보냅니다. 그림 위 좌표 지정은 아직 지원하지 않습니다.
- 창 툴바: 커서 키 메뉴(키 설명과 단축키)와 콜론 명령 팝오버(`:` 키로도 열림). 한 글자 질문은 입력 대기 창에서 답하며, 빈 답은 Return입니다.
- 커서 요청에 함께 기록하는 IRAF 출력(`interaction.json`의 `prompt`)은 직전 요청 이후 작업이 출력한 줄이며, 실행 스크립트와 입력 반향은 뺍니다.
- `GET /api/display`는 프레임 목록과 갱신 번호를 돌려줍니다.

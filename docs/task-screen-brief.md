# GIRAF task 화면 설계 브리프

상태: 사용자 확정 완료 (2026-09-15)

## 1. 사용자와 목적

- 주 사용자는 IRAF를 배우는 천문학 학생이며, 제품은 범용 IRAF 작업 환경을 지향합니다.
- 모드: **Operate**. 사용자가 파일과 파라미터를 제어하고, 실행 결과를 확인하여 다음 작업에 사용할 수 있어야 합니다.
- 주요 흐름은 bias·dark·flat 자료로 필요한 master를 만든 뒤 science 영상에 보정을 적용하는 것입니다. 이 흐름의 일부 실행, 반복, 재결합, 분기와 외부에서 만든 master 사용도 동등하게 지원합니다.
- 두 수업 문서는 작업 사례입니다. 특정 파일 수, 노출시간, 필터, gain, rejection, 통계 영역, 보정 순서나 기본값을 제품 규칙으로 채택하지 않습니다.

## 2. 선택한 구조: 연결 작업도

사용자가 세 시안 중 **연결 작업도**를 선택했습니다.

시안: [task-map.png](../.impeccable/mocks/decision/task-map.png)

- **왼쪽 — 자료와 task:** 폴더, 저장한 선택, 실행 결과, 보정 기준 자료를 탐색합니다. 패키지 경로와 task 이름·한국어 설명으로 검색하여 작업을 추가합니다.
- **중앙 — 연결 작업도:** 파일/선택 묶음 → task → 결과의 관계를 보여 줍니다. 생성할 작업을 자유롭게 추가하고 입력 역할을 지정합니다. 전체 흐름 보기, 선택한 작업에 집중하기, 목록 보기로 전환할 수 있습니다.
- **오른쪽 — task 상세:** 선택한 작업의 입력, 처리 설정, 보정 기준, 출력, 관련 패키지 설정을 편집합니다. 작업도는 맥락을 유지하고 상세 패널이 편집 공간을 맡습니다.
- **하단 — 실행 기록:** 실행 상태, 결과, 로그, 명령과 적용된 설정을 확인합니다. 기록을 선택하면 해당 작업과 결과가 함께 강조됩니다.

GIRAF의 기존 단색 화면, 글꼴 계열, 표·폼·버튼 체계를 이어갑니다. 구조를 구분하는 데에는 정렬, 선, 영역과 상태 표기를 사용합니다. 시안의 예시 파일명과 개별 컨트롤은 기능 명세가 아니며, 실제 파라미터 의미는 아래 기준을 따릅니다.

## 3. 핵심 사용 동선

### A. 자료에서 master 만들기

1. 파일 목록에서 원하는 자료를 선택하고 **task에 사용**으로 작업을 만듭니다. task를 먼저 추가한 뒤 자료를 지정하는 순서도 가능합니다.
2. 입력 개수, 순서, 유형, subset, 노출시간과 헤더를 확인합니다. 파일명 추정과 IRAF가 해석한 값은 구분하여 표시합니다.
3. 결합 방법, rejection, scaling과 관련 세부 설정을 조정합니다. `process=yes`이면 같은 상세 패널 안에 실제 적용될 `ccdproc` 설정과 보정 기준 자료가 나타납니다.
4. 출력 이름·경로와 입력 대응을 확인하고 **실행**합니다. 실행 버튼은 현재 설정을 검증한 뒤 실행하며, 별도의 검증 버튼 클릭을 매번 요구하지 않습니다. 상세 실행 계획은 필요할 때 먼저 열 수 있습니다.
5. 결과를 영상·헤더·통계로 확인합니다. 결과의 **입력으로 사용**에서 대상 작업과 역할을 선택합니다. 예: `ccdproc.dark`, `ccdproc.flat`, 재결합 작업의 `input`.

### B. science 영상 보정하기

1. science 자료를 `ccdproc.images`에 지정합니다.
2. 적용할 보정을 켜고 바로 옆에서 기준 영상을 지정합니다. `zerocor`와 `zero`, `darkcor`와 `dark`, `flatcor`와 `flat`을 떨어뜨리지 않습니다.
3. 실행 계획에서 자료별 기준 영상 대응, 이미 수행된 처리, 예상 제외와 출력 경로를 확인합니다. 확정하지 못한 내용은 **실행 시 확인**으로 표시합니다.
4. 실행 후 처리됨·건너뜀·실패·사용자 입력 대기를 구분하여 확인합니다. 입력/결과를 비교하고, 설정을 바꿔 새 실행을 만들거나 다른 task로 이어갑니다.

### C. 흐름을 끊지 않고 헤더 수정하기

1. 입력 목록에서 헤더를 확인하다가 **ccdhedit으로 편집**을 엽니다. 호출한 작업과 현재 선택을 유지합니다.
2. 논리적 항목명과 기기 매핑 후 실제 키, 기존 값, 변경 값, 자료형을 나란히 확인합니다.
3. 적용 결과를 확인한 뒤 **이 결과로 입력 교체**로 원래 작업에 돌아옵니다. 다른 작업의 입력은 자동 교체하지 않습니다.
4. `value=""`가 헤더 삭제를 뜻한다는 것을 명시합니다. 처리 이력 키 편집도 숨기지 않으며, 무엇을 바꾸는지 미리 보여 줍니다.

### D. 문제를 고치고 이어가기

- 오류 요약을 누르면 문제가 있는 파일·설정·연결로 이동합니다. 작성한 나머지 설정과 선택은 유지합니다.
- 작업을 다른 곳에서 열거나 영상·도움말을 확인한 뒤 돌아와도 선택 노드, 스크롤, 확대와 초안이 유지됩니다.
- 실행 당시의 설정은 고정된 기록입니다. 과거 설정을 불러올 때 새 초안을 만들며 과거 결과를 현재 설정의 결과처럼 표시하지 않습니다.

## 4. 연결과 설정의 의미

### 작업도

- 노드에는 자료, task 인스턴스, 결과가 있습니다. 동일한 task를 여러 번 추가할 수 있으며 설정은 인스턴스별로 보관합니다.
- 연결선에는 `images`, `input`, `zero`, `dark`, `flat`처럼 목적지의 실제 입력 역할을 표시합니다. `ccdproc.zero`와 `combine.zero`처럼 같은 이름의 서로 다른 의미를 혼동하지 않도록 task 문맥을 붙입니다.
- 완성된 결과 연결은 **해당 실행의 결과 버전**을 가리킵니다. 상위 작업을 다시 실행해도 하위 입력을 새 결과로 자동 교체하지 않습니다. 교체할 결과를 고르는 동작을 제공합니다.
- 생성 예정 결과도 관계를 설계할 수 있지만 **입력 대기**로 표시합니다. 연결 자체는 실행하지 않습니다. 실제 실행 시 사용할 자료가 모두 준비되어야 합니다.
- 연결 해제는 입력 관계를 제거하는 동작입니다. 파일 삭제나 실행 기록 삭제와 분리합니다.
- 끌어서 연결하기 외에 **입력 연결 → 자료 선택 → 역할 지정**과 키보드 조작을 제공합니다. 목록 보기는 같은 작업/연결 모델의 동등한 편집 화면입니다.
- 외부 master, 일부 보정만 수행하는 작업, master 재결합, 독립된 헤더/통계 작업을 허용합니다. 자동 일괄 실행은 이번 핵심 흐름에 포함하지 않습니다.

### 전체 파라미터 접근

- 파라미터는 의미별 그룹과 검색 가능한 **전체 파라미터** 표로 제공합니다. 두 보기는 같은 값을 편집합니다.
- IRAF 식별자, 한국어 설명, 값/표현식, 자료형, 기본값과의 차이, 값의 출처, 적용 조건을 확인할 수 있습니다.
- 관련 옵션을 먼저 보여 주되, 현재 적용되지 않는 값도 전체 보기에서 확인·수정할 수 있습니다. 조건 변경만으로 기존 값을 지우거나 실행값을 조용히 바꾸지 않습니다.
- 빈 문자열, `INDEF`, 숫자/헤더키, 목록/표현식은 해당 task의 문법대로 보존합니다. 예를 들어 `ccdtype`의 빈 값은 단순한 미입력 오류로 취급하지 않습니다.
- task 기본값 복원, 항목별 복원, 사용자 저장 설정을 구분합니다. 수업 예시 값을 기본값으로 덮어쓰지 않습니다.

### 연관 설정과 공유 범위

- 결합 task 안에서 `ccdproc` 전처리를 확인·편집합니다. 보정 스위치와 필요한 파일·영역·피팅 설정을 가까이 둡니다.
- 새 작업은 공통 설정의 특정 버전을 가져오고, 수정은 기본적으로 해당 작업에만 적용합니다. 다른 열린 작업에 영향을 주는 공통 설정 갱신은 대상과 변경 차이를 명시한 별도 동작으로 제공합니다.
- 실행 기록에는 task, 전처리, 패키지, 기기 매핑을 합친 **실효 설정**을 저장합니다.
- 전처리가 실제로 수행할 작업은 입력 유형·헤더 이력·기준 자료에 따라 달라집니다. 모든 입력에 모든 보정이 적용된다는 식으로 표현하지 않습니다.

## 5. IRAF 완전 제어에 필요한 범위

범위의 기준은 **설치된 IRAF 버전에서 각 task가 실제 지원하는 동작**입니다. 기존 앱이 제한한 기능도 설계와 실행 계층 확장에 포함합니다. 주요 진입점은 `noao.imred.ccdred`의 `zerocombine`, `darkcombine`, `flatcombine`, `combine`, `ccdproc`, `ccdhedit`이며, 패키지 탐색과 상세 편집 구조는 다른 task에도 확장 가능해야 합니다.

| 대상 | 화면에서 제어할 내용 | 실행 계층에 필요한 확장 |
| --- | --- | --- |
| 결합 task | 입력 순서·표현식, 유형 선택, 결합/rejection/scaling, 통계 영역, 전처리, task가 지원하는 subset, 출력 | 표현식과 참조 자료 해석, 실제 IRAF 분류/출력 대응, 관련 설정의 실행별 고정 |
| `combine` | 해당 버전의 마스크, offsets, project, scale/zero/weight 파일·헤더 표현식, 추가 출력 등 | 마스크·헤더 참조 파일 추적, 지원 차원의 자료 처리, 보조 파일 순서 보존 |
| `ccdproc` | 모든 처리 스위치, 보정 기준, 영상 영역, 축, scan/readout, overscan fitting, `interactive`, `noproc` | 대화형 세션/그래픽/커서 응답, 기존 처리 이력 해석, 기준 자료 선택과 사전 처리의 의미 보존 |
| `ccdhedit` | 모든 지원 항목과 자료형, 추가·수정·삭제, 기기 키/값 변환 | 변경 전후 기록, 입력 작업으로 결과 반환, 여러 편집을 묶을 경우 개별 호출과 부분 완료 기록 |
| 패키지 설정 | instrument/subset 파일, 출력 자료형, 로그·그래픽·백업 등 해당 버전의 설정 | 현재 관리/고정하는 항목의 공개, 사용자 설정과 내부 실행 환경의 명시적 대응 |
| 입출력 | 명시 경로, 지원 목록·패턴·영상 section, 원본/사본 대상, task가 지원하는 삭제·덮어쓰기 의미 | 표현식을 임의 shell 실행으로 바꾸지 않는 IRAF 문법 처리, 파일 대응·백업·충돌 처리 |

### 원본 보존과 파일 제어

- 기본은 보호 사본에서 실행합니다. 이때 IRAF가 실제로 읽고 변경할 대상과 사용자가 보는 이름의 대응을 공개합니다.
- 사용자가 지정 파일을 직접 대상으로 삼는 경우에는 변경·삭제·덮어쓰기 대상과 백업/복구 조건을 실행 계획에 명시합니다. 지원하지 않는 파일 동작을 지원하는 것처럼 조용히 흉내 내지 않습니다.
- IRAF 자체가 거부하거나 폐기한 옵션은 그 버전의 설명과 이유를 표시합니다. 웹 UI가 옵션을 제공한다고 IRAF 기능이 확장되는 것은 아닙니다.
- 알려진 차이 예: 현재 앱은 `interactive=no`를 강제하고 `combine`의 마스크·project·일부 표현식을 제한합니다. 파라미터 정의는 2.18.1 스냅샷입니다. 실행 시 버전·task 정의와 비교할 능력 정보가 필요합니다.
- 공개 `combine` 문서는 `clobber`에 대해 폐기 안내와 과거 설명을 함께 담고 있습니다. 해당 설치본의 도움말·소스·동작 검증으로 판정하고, 모든 버전에서 덮어쓰기가 가능하다고 약속하지 않습니다.

## 6. 상태, 자료 규모와 반응형 동작

- **처음/비어 있음:** 자료 열기와 task 추가가 바로 보입니다. 템플릿을 쓰지 않고 빈 작업도에서 시작할 수 있습니다.
- **편집 중:** 저장 상태와 변경된 항목을 표시합니다. 외부 파일 변경, 경로 소실, 설정 버전 차이는 해당 자료/작업 옆에서 알립니다.
- **검증:** 통과, 확인 필요, 실행 불가를 구분합니다. 추정과 IRAF 확인 결과를 구분하고, 설정 변경 시 오래된 검증 결과를 무효화합니다.
- **실행 중:** 준비·실행·사용자 입력 대기·중단 요청·완료·건너뜀·부분 실패·실패를 구분합니다. 근거 없는 진행률이나 완료 예측을 만들지 않습니다.
- **대화형 처리:** 대기 중인 task, 대상 영상, 그래픽과 현재 요구 동작을 상세 패널에 표시합니다. 이어하기/종료/중단을 구분하고 연결 복구 후 세션 상태를 확인합니다.
- **많은 자료:** 입력 수를 고정하지 않습니다. 큰 선택 묶음은 대표 요약과 펼치기, 표의 가상화/분할 로딩을 사용하며 실제 입력 순서를 유지합니다. 성능 검증에 사용할 자료 규모와 상한은 구현 전 측정할 항목입니다.
- **많은 작업:** 자동 배치, 그룹 접기, 검색, 선택 작업의 상·하위 관계 강조, 목록 보기를 제공합니다. 모든 노드를 한 화면에 억지로 축소하지 않습니다.
- **넓은 화면:** 자료 목록·작업도·상세 패널을 함께 사용하고 영역 크기를 조절할 수 있습니다.
- **작은 노트북:** 상세 패널을 확장하고 자료 목록을 접습니다. 그래프 맥락과 돌아갈 위치를 유지합니다.
- **좁은 화면:** 자료/작업/상세를 전환하고 목록 보기를 우선 제공합니다. 핵심 조작을 그래프 드래그나 마우스 hover에만 의존시키지 않습니다.
- 키보드 탐색, 명확한 초점/선택, 텍스트로 읽는 연결 관계와 상태, 색 이외의 오류 표기, 확대 시 재배치와 reduced-motion 대응을 구현 요구사항에 포함합니다.

## 7. 완료 판단과 경계

이 브리프의 설계가 구현되었다고 판단하려면 다음을 확인할 수 있어야 합니다.

1. 사용자가 임의의 자료 묶음으로 master를 만들고, 결과를 원하는 task의 정확한 입력 역할에 지정할 수 있습니다.
2. 실제 실행에 영향을 주는 task·전처리·패키지 설정을 현재 작업에서 확인하고 제어할 수 있습니다.
3. 입력 파일 확인, 헤더 수정, 영상 비교, 실행 실패 복구가 초안이나 선택 맥락을 잃지 않고 이어집니다.
4. 전체 파라미터·표현식·대화형 기능의 지원 여부를 설치 버전과 대조할 수 있습니다. 화면 노출만으로 완전 지원을 주장하지 않습니다.
5. 두 수업 예시 외에도 외부 master 사용, 다른 subset, 일부 보정, 재결합과 독립 task가 같은 구조로 표현됩니다.

이번 산출물은 선택한 화면 구조와 동작의 설계 브리프입니다. 실제 앱 구현, 모든 IRAF 패키지의 즉시 지원, 자동 처리 파이프라인 실행과 새로운 과학적 보정 알고리즘은 별도 구현 범위입니다. 테스트를 작성하는 구현 작업에서는 사용자 지침대로 구현 코드보다 테스트 작성을 먼저 완료합니다.

아직 확정하지 않은 사항은 기능별 구현 순서, 대화형 IRAF 세션 연결 기술, 자료 규모별 성능 한도와 추가 패키지의 상세 지원 목록입니다. 이 결정을 구현자가 기능 축소나 수업 전용 규칙으로 임의 대체해서는 안 됩니다.

## Direction contract

- **THESIS:** 자료 → task 인스턴스 → 특정 실행 결과의 관계를 유지하면서 선택 작업의 실제 IRAF 설정을 편집합니다.
- **OWN-WORLD:** 승인 시안의 흰 배경, 단색 글자, 얇은 구분선과 기존 Inter·Base UI 폼을 유지합니다. 밝은 실습실에서 긴 시간 파일과 파라미터를 비교하는 사용 환경을 기준으로 합니다.
- **STORY:** 자료를 지정하고, 생성 예정과 이미 만들어진 결과를 구별하며, 실행 결과를 사용자가 선택한 다음 입력에 연결합니다.
- **FIRST VIEWPORT:** 상단 앱 바, 왼쪽 자료·패키지 탐색 약 16%, 중앙 연결 작업도 약 52%, 오른쪽 상세 약 32%, 중앙과 상세 아래 실행 기록입니다. 주 실행 버튼은 상세 상단에 둡니다. 좁은 화면은 목록과 패널 전환을 사용합니다.
- **FORM:** 사용자가 선택한 dependency-map, 승인 키 `1def46f4`, 브리프 확인 키 `5de3256c`. `.impeccable/mocks/decision/task-map.png`의 구조를 계승합니다. 파일명과 예제 노드 내용은 실제 작업 자료에 따라 달라집니다.
- **FINISH:** unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

## 2026-09-16 갱신 — 임의 워크플로 편집기

이 절과 [워크플로 편집기 문서](workflow-editor.md)가 앞선 화면 구조 서술과 충돌하면 최신 방향을 우선합니다. 사용자는 중앙 노드 캔버스로 임의의 IRAF 워크플로를 구성하고 오른쪽 inspector에서 선택한 task의 설정을 제어하도록 확정했습니다. master 생성·science 보정은 사례이며 고정된 주 동선이나 제품 규칙이 아닙니다.

이번 구현은 task 인스턴스당 하나의 노드에 입력 요약과 결과 포트를 묶습니다. 노드 이동은 포인터와 Alt+방향키, 삭제는 눈에 보이는 버튼과 되돌리기로 제공합니다. 파일/task 탭은 교대 표시하며 실행 기록은 모든 화면 크기에서 기본 접힘입니다. 표현식은 항상 편집 가능하고 Boolean switch와 조건부 보정 필드를 사용합니다. 전체 파라미터는 폼이며 초기값 비교 표와 반복된 선택/저장 배지·안내문은 기본 편집 화면에서 제거합니다. 초기 파라미터와 인스턴스별 설정, backend 실행 의미, 특정 결과 버전의 명시적 선택은 보존합니다. 비활성 연결은 점선으로 구분합니다.

이전 비율·표 구조·좁은 화면 목록 우선 서술 대신 실제 반응형 치수와 동작은 최신 문서를 따릅니다. 시각 토큰은 [DESIGN.md](../DESIGN.md)에 기록합니다. 이전 브리프의 설치 버전별 지원 요구나 장기 기능 목록을 이번 UI 변경으로 모두 구현했다고 해석하지 않습니다.
